# 贸智库 TradeMind · 企业 AI 服务交付平台

一个面向中小企业（尤其是外贸 / 制造类）的 **AI 服务交付平台** 前端原型。

它要解决的不是「让企业自己研究 AI 工具」，而是把原本需要顾问亲自完成的服务流程，拆成 **十个可执行、可检查、可验收的步骤**：资料怎么准备、环境怎么检查、知识库怎么建、助手怎么配、做到什么程度算交付完成。

> 本仓库是 **产品原型**，使用纯静态前端实现，所有数据保存在浏览器本地（localStorage），不连接任何真实后端与模型服务。

### 从服务商视角建一个新客户

这是完整闭环，建议按这个顺序试：

1. 打开 `admin.html`，用服务商账号登录
2. 点「+ 新建客户」，填企业名称和联系人（必填），选服务与金额
3. 创建成功后会问「现在进入」——点它，就会以该企业管理员身份打开空白工作空间
4. 从第 1 步开始走，填企业信息、上传资料、跑测试、邀请员工
5. 回到后台，该客户的阶段和进度已经自动回写（0% → 实施中 → 验收中 → 维护期）

每个客户的数据是分开存的，从后台点「进入」可以随时来回切换，互不覆盖。

## 为什么不是普通官网

普通企业官网解决「让客户了解你」，这个平台解决「让客户知道事情做到哪一步了」。

四个能力叠在一起：

1. **服务选购** —— 客户选择想解决的问题，而不是先买一套软件
2. **项目向导** —— 网站告诉客户每一步做什么、为什么做、怎么操作
3. **自动执行** —— 能自动完成的（解析、切片、建索引）由平台直接做
4. **交付验收** —— 用 50 道业务测试题检查是否真的达标，通过率 85% 才进入验收

## 十步交付流程

以「企业 AI 知识库建设」为主线，每一步都包含五段信息：**做什么 / 为什么做 / 怎么操作 / 自动执行 / 完成检查**。

| # | 步骤 | 责任方 | 自动执行 |
| --- | --- | --- | --- |
| 1 | 企业信息确认 | 客户填写 | — |
| 2 | 电脑及环境检查 | 本地工具检查 | 系统自检 |
| 3 | 企业资料整理 | 客户操作 | 解析文件、生成清单 |
| 4 | 知识库创建 | 平台执行 | 切片、向量化、建索引 |
| 5 | AI 模型配置 | 客户授权 | 测试模型连通性 |
| 6 | AI 助手创建 | 平台执行 | 按模板生成助手 |
| 7 | 知识库测试 | 双方测试 | 50 题批量运行 |
| 8 | 员工试用 | 客户操作 | — |
| 9 | 项目验收 | 双方确认 | 汇总生成报告 |
| 10 | 正式交付 | 交付完成 | 账号 / 备份核验 |

**完成检查是硬门槛**：所有检查项勾选完毕，「完成这一步」按钮才可点击；完成后才解锁下一步。

### 可以真正走通的四步

其余步骤是流程说明，这四个做成了真实交互，数据会落盘并在页面间联动：

**第 1 步 · 企业信息确认**

- 表单输入即保存，不需要点「保存」按钮，刷新不丢
- 企业名改动会同步到侧边栏和设置页
- 三个必填项（企业名 + 行业 / 主营类别 / 使用目标 ≥10 字）决定检查项是否满足
- 把必填项清空，这一步会从「已完成」退回「进行中」，并给出提示

**第 3 步 · 企业资料整理**

- 拖拽或点选文件，浏览器只读取文件名、大小、格式 —— 文件不出本机
- 按文件名自动归类（`产品目录` → 产品资料，`SOP` → 业务流程，`售后/退换` → 售后资料），每份都能手动改
- 拒绝非白名单格式、超过 200 MB 的文件，同名文件自动去重
- 四类资料的覆盖度实时显示，缺哪类一眼能看到
- 检查项跟着资料自动核验；把产品资料删光，这一步会退回「进行中」，进度条同步下降

**第 7 步 · 知识库测试**

- 生成 50 道题：产品 24 / 销售 14 / 邮件 8 / 安全 4
- 批量运行，逐条给出 AI 回答与引用出处
- 12 道关键题必须人工判定（通过 / 需修改 / 资料不足），可以改判，统计实时更新
- 通过率 ≥ 85% 且关键题全部核对，才允许生成报告
- 报告写入后，「测试与验收」页读的是同一份数据，不是写死的示例

**第 8 步 · 员工试用**

- 邀请成员：校验邮箱格式、查重、写入成员表，「成员与权限」页同步
- 提问计数来自「员工门户」的真实问答，问 5 次自动满足条件
- 可以记录试用反馈，反馈内容回流到本步骤
- 成员被移除导致人数不足时，本步骤退回「进行中」

## 功能模块

### 客户端（app.html）

- **工作台** —— 项目进度、待办事项、最近动态、服务入口
- **服务商城** —— 三项服务对比、选购流程、诊断预约
- **项目向导** —— 十步流程、逐步检查、自动执行控制台、人工协助入口
- **配置中心** —— 模型管理 / API 与授权 / 知识库 / 资料文件 / AI 助手 / 提示词规则
- **成员与权限** —— 成员列表、四类角色权限矩阵
- **测试与验收** —— 四类测试、可运行的测试流程、86% 通过率报告、验收确认
- **员工门户** —— 带引用出处的问答界面、答不上来的问题、资料补充建议
- **操作与运行记录** —— 授权范围与撤销、操作审计
- **设置** —— 企业信息、数据存储策略、账号安全、演示数据重置

### 服务商后台（admin.html）

- 独立登录页（服务商账号，与客户端账号分离）
- 4 项经营指标（客户总数 / 进行中项目 / 合同总额 / 待处理协助），全部实时计算
- 按阶段划分的项目看板（待启动 → 实施中 → 验收中 → 维护期）
- 客户与项目清单（含健康度标记、项目编号、进入按钮）
- **新建客户**：写入客户档案 + 同步生成空白企业工作空间
- **以客户身份进入**：切换到该企业视角查看它实际看到的东西
- 客户端的任何进度变化都会回写后台的进度与阶段
- 人工协助请求处理、我的任务、交付模板沉淀

## 技术说明

纯静态，零依赖，零构建：

```
gsmett/
├── index.html          登录 / 注册
├── app.html            企业工作空间（客户端）
├── admin.html          服务商后台
└── assets/
    ├── css/app.css     设计系统（约 900 行）
    ├── js/data.js      业务模型、种子数据、图标库、工具函数
    └── js/app.js       路由、视图渲染、交互逻辑
```

- **无框架**：原生 DOM + 模板字符串，避免原型阶段引入构建链
- **无外部请求**：字体走系统栈，图标为内联 SVG，离线可用
- **状态持久化**：`localStorage` 键 `tm_state_v3`，刷新不丢；设置页可一键重置
- **路由**：hash 路由（`#wizard/6`、`#config/model`），可前进后退
- **响应式**：1440 / 980 / 860 / 620 四个断点，移动端侧边栏收起

### 本地运行

```bash
# 任意静态服务器均可
python -m http.server 8080
# 或
npx serve .
```

直接双击 `index.html` 也能打开（无跨域依赖）。

## 一个重要的边界

平台负责 **引导、配置、检查、管理**；真正涉及客户电脑、服务器、文件、模型 API 的操作，必须经由客户授权的本地执行程序或人工确认完成。

具体来说：

- 平台 **没有** 远程命令执行能力
- 服务顾问 **看不到** 客户的资料内容，只能在授权后查看部署状态与错误日志
- 授权范围明确、可随时撤销、全程留痕
- 客户资料默认存放在企业自有环境，平台只保存流程与状态信息
- 即使文件存在本地，检索片段与提问仍会发送到模型服务商 —— 这是 RAG 架构的固有数据流，必须由企业书面确认

这些约束在产品里都做成了可见的界面元素（授权卡片、边界提示、数据策略表），而不是藏在协议里。
