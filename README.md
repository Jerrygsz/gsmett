# 贸智库 TradeMind · 企业 AI 服务交付平台

> 本地服务版：知识库真的建、文件真的解析、回答真的由模型生成。
> 不是静态原型，数据落在 `data/` 目录，刷新不丢，换浏览器也在。

## 怎么启动

双击 **`启动服务.bat`**，等浏览器自动打开 `http://localhost:8787`。

首次启动会自动装依赖（约 1 分钟）。之后每次双击即可，关掉黑窗口就停止服务。

命令行方式：

```bash
npm install     # 只需一次
npm start       # 启动，默认只监听 127.0.0.1:8787
```

**默认只允许本机访问**，因为这个服务没有登录鉴权——一旦开放到局域网，
同网络里的任何人都能调用 `/api/clients/:id/chat`，用你的模型额度白嫖。

确实要让手机或同事打开时，显式放开：

```bash
HOST=0.0.0.0 npm start        # macOS / Linux / Git Bash
$env:HOST="0.0.0.0"; npm start # Windows PowerShell
```

终端会打印局域网地址（如 `http://192.168.1.104:8787`）和一行警告。
只在可信网络里这么用，用完就关。

## 三步走完一轮

1. 打开 `admin.html`，用 `admin@maozhiku.com` / `maozhiku2026` 登录（或直接 `admin.html?demo=1`）
2. 点「+ 新建客户」，填企业名称和联系人
3. 创建后点「现在进入」，从第 1 步开始走

## 模型 Key 怎么配（客户自己带）

**本平台不内置、也不补贴任何模型。** 每个客户在第 5 步填自己的 API Key，费用记在客户自己的服务商账号上——平台看不到、也不替客户付。

- 第 5 步列出多家「提供免费额度」的服务商（DeepSeek / 硅基流动 / 通义千问 / 智谱 GLM / 月之暗面）。点「填入」自动填好接口和模型，再去该平台申请一个**属于你自己**的免费 Key 粘贴即可。
- 也支持 OpenAI 等任意 OpenAI 兼容接口，选「自定义」手填接口与模型。
- 保存时会真的发一次请求验证，不通不让保存。
- 浏览器永远拿不到明文 Key，接口只返回打码形式。

服务商后台创建 Key 后，加密存在本机 `data/` 目录，只用于调用模型，不进任何网页代码、不上传平台。

> 早期版本在 `data/config.json` 里内置了一把平台 DeepSeek Key 给所有客户共用，现已移除——客户必须自带 Key。管理员仍可在 `data/config.json` 里「可选」配一个平台默认 Key 仅供自检连通性，但它**不会自动补贴**客户请求。

## 数据存在哪

```
data/
  config.json               可选的平台默认模型 Key（加密存储，不进 Git；默认留空，客户需自带）
  .machine-salt             加密用的随机盐（换机器解不开，不要外传）
  platform.json             后台登录账号（密码加密）+ 服务商人员名单
  tickets.json              客户端提交的工单（协助 / 诊断 / 开通申请）
  clients.json              客户列表
  clients/<id>/state.json   企业信息、步骤进度、成员、模型配置、验收记录
  clients/<id>/docs.json    资料元数据（文件名、页数、字数、分类）
  clients/<id>/index.json   切片与倒排索引
  clients/<id>/uploads/     你上传的原始文件
```

备份就复制整个 `data/` 目录（**要连 `.machine-salt` 一起**，否则 Key 解不开）。删客户会连同资料一起删除。

## API Key 怎么存的

**存的是密文，不是明文。**

`data/config.json` 和客户 `state.json` 里的 `apiKey` 长这样：

```json
"apiKey": "enc1:W21FNxAKA8WhUttX:oRyvgV/vCwAv3ppADtOV3w==:nN99QVhy..."
```

算法是 AES-256-GCM，密钥由 **主机名 + 系统用户名 + `data/.machine-salt`** 用 scrypt 派生。

**能挡住：**

- 备份目录、`data/` 被复制到别的电脑 → 解不开
- 误传网盘 / 发微信 / 提交 Git → 看到的是乱码
- 硬盘被单独拆走读盘 → 换机器解不开

**挡不住（必须说清楚）：**

- 你这台电脑上、用你这个 Windows 账号跑的任何程序，都能解密。要挡这个得用系统凭据库（Windows DPAPI），需要额外原生模块，本机装不上
- 服务运行期间，Key 一定存在于进程内存里
- **没有登录鉴权的服务不要绑到局域网**。所以服务默认只监听 `127.0.0.1`，同 WiFi 的人访问不到

换 Key 不用开浏览器：

```bash
node tools/set-key.js          # 交互输入，会先验证能用再保存
```

旧数据里如果有明文 Key，服务启动时会自动加密，日志会打印「已将 N 处明文 Key 加密存储」。

想确认当前状态：

```bash
grep -r "sk-" data/ --include="*.json"   # 应该一条都搜不到
```

## 为什么不是普通官网

普通企业官网解决「让客户了解你」，这个平台解决「让客户知道事情做到哪一步了」。

四个能力叠在一起：

1. **服务选购** —— 客户选择想解决的问题，而不是先买一套软件
2. **项目向导** —— 网站告诉客户每一步做什么、为什么做、怎么操作
3. **自动执行** —— 能自动完成的（解析、切片、建索引）由平台直接做
4. **交付验收** —— 由模型从客户自己的资料里出题，逐题核对，通过率达标且全部判定完才进入验收

## 十步交付流程

以「企业 AI 知识库建设」为主线，每一步都包含五段信息：**做什么 / 为什么做 / 怎么操作 / 自动执行 / 完成检查**。

| # | 步骤 | 责任方 | 自动执行 |
| --- | --- | --- | --- |
| 1 | 企业信息确认 | 客户填写 | — |
| 2 | 电脑及环境检查 | 本地工具检查 | 系统自检 |
| 3 | 企业资料整理 | 客户操作 | 解析文件、生成清单 |
| 4 | 知识库创建 | 平台执行 | 切片、向量化、建索引 |
| 5 | AI 模型配置 | 客户授权 | 测试模型连通性 |
| 6 | AI 助手创建 | 平台执行 | 按模板生成助手 |
| 7 | 知识库测试 | 双方测试 | 50 题批量运行 |
| 8 | 员工试用 | 客户操作 | — |
| 9 | 项目验收 | 双方确认 | 汇总生成报告 |
| 10 | 正式交付 | 交付完成 | 账号 / 备份核验 + 开启使用 |

**完成检查是硬门槛**：所有检查项勾选完毕，「完成这一步」按钮才可点击；完成后才解锁下一步。

### 可以真正走通的六步

其余步骤是流程说明，这五个做成了真实交互，数据会落盘并在页面间联动：

**第 2 步 · 电脑及环境检查**

这一步是**真的在读你的机器**，不是写死的演示文案。点「开始检查」后：

| 浏览器实测（6 项） | 数据来源 |
| --- | --- |
| 操作系统 | `userAgentData.getHighEntropyValues()`，能区分 Windows 10 / 11 并读出 x86 · 64 位 |
| 浏览器 | 同上，真实品牌与版本 |
| 逻辑处理器 | `navigator.hardwareConcurrency` |
| 设备内存 | `navigator.deviceMemory`（浏览器为隐私封顶在 8 GB，界面上已注明） |
| 网络状态 | **真发一个 HEAD 请求测往返时延**，不是 `connection.rtt` 的估算值 |
| 网页存储配额 | `navigator.storage.estimate()`，已注明「网页存储上限，不等于磁盘剩余」 |

另有 4 项浏览器**无权读取**，界面上一律标成「浏览器无权读取」并说明原因，不编数字：

- 系统盘可用空间（`≥ 40 GB` 需自己打开资源管理器确认）
- 处理器具体型号（浏览器只给核心数）
- Docker Desktop 是否安装
- 3000 端口是否被占用

这三项落在检查项里就是「需要人工确认」，而不是假装测过了。**这一步正好用来回答客户最常问的「网站能不能直接读我的电脑」——能读的读，读不到的明确说为什么，顺带把本地助手的必要性讲清楚。**

判定规则：浏览器侧有告警（如手机访问、离线、内存 < 8 GB）时，检查项不会自动勾上，第 2 步会退回「进行中」，并提示你应该在哪台机器上重做。

**第 1 步 · 企业信息确认**

- 表单输入即保存，不需要点「保存」按钮，刷新不丢
- 企业名改动会同步到侧边栏和设置页
- 三个必填项（企业名 + 行业 / 主营类别 / 使用目标 ≥10 字）决定检查项是否满足
- 把必填项清空，这一步会从「已完成」退回「进行中」，并给出提示

**第 3 步 · 企业资料整理**

- 拖拽或点选文件，浏览器只读取文件名、大小、格式 —— 文件不出本机
- **可以直接说人话让它扫硬盘**：输入「桌面」「下载文件夹」「D盘的公司资料」，系统按这台电脑的真实目录解析成绝对路径，递归找出可建库的文档后导入；找不到时会列出候选文件夹让人点选
- 按文件名自动归类（`产品目录` → 产品资料，`SOP` → 业务流程，`售后/退换` → 售后资料），每份都能手动改
- 拒绝非白名单格式、超过 200 MB 的文件，同名文件自动去重
- 四类资料的覆盖度实时显示，缺哪类一眼能看到
- 检查项跟着资料自动核验；把产品资料删光，这一步会退回「进行中」，进度条同步下降
- **扫描件识别（OCR）**：图片型 PDF 没有文字层，先渲染成图片，交给多模态模型逐页读字，结果存成 `<docId>.ocr.txt` 并并入知识库，识别完自动重判分类
- **AI 分析分类**：读正文（不是文件名）判定四类之一，给出判断依据，并写出「这份资料能回答什么问题」（2–3 个员工真会问的问题）
- **能回答什么**：问题清单会显示在资料行上、第 6 步挑助手范围时作为参照、员工门户的「试试这样问」也由它生成

> 「说人话扫硬盘」的解析顺序：① 真实存在的路径直接采用 → ② 去掉「帮我扫描一下」这类动词 → ③ 识别 `桌面/下载/文档/图片/微信文件` 等系统目录别名 → ④ 识别 `D盘 / D: / D盘的公司资料` 盘符写法 → ⑤ 只给文件夹名时，在桌面、文档、下载、用户目录和各磁盘浅层按名称模糊匹配。多个目录用逗号、顿号、分号或换行分开；`桌面和下载` 这种说法也会自动拆开。加了文件夹之后，随时点「重新扫描」就能把新文件补进知识库，已建库的会自动重建索引。

**扫描件 OCR 的实现与边界**

- 用 `pdfjs-dist` 把 PDF 前 N 页渲染到 `@napi-rs/canvas`（白底、宽 1600px、JPEG 82），再以 `image_url` 交给多模态模型。不依赖本机装 Tesseract，也不上传原文件，只上传页面图片。
- 视觉模型按服务商自动挑：智谱 `glm-4v-flash`（默认，便宜）、通义 `qwen-vl-max`、OpenAI `gpt-4o-mini`、Moonshot `moonshot-v1-8k-vision-preview`。DeepSeek 的对话模型没有视觉能力，会明确提示换一家，而不是报 400。
- `glm-4v-flash` 的 `max_tokens` 上限是 1024，所以单页大约能转写 700–900 字；篇幅更长的扫描手册建议直接给文字版。
- 服务端每批最多 4 份、批内并发 2，前端循环推进并显示进度；单份约 10 秒。识别出来少于 10 个字的记为失败（纯图片页或太模糊），不写空文件。
- 只对 `scanned / empty / chars<20` 的 PDF 触发，文字版 PDF 完全不会走这条路，避免白花 token。

**第 6 步 · AI 助手创建**

这一步配的东西会真的进入模型调用，不是写给人看的说明：

- **提示词**：助手的名称、岗位定位、语气、补充要求，会拼成一段「当前助手设定」写进 system prompt。
- **回答规则**：四个开关直接对应模型约束——必须能对上资料、查不到就说不知道、先给结论、价格只引原文。
- **资料范围**：勾选的分类真的作用在**检索**和**出题**上。范围外的切片不会被检索到，也不会被拿去出题；问到范围外的问题，助手会直接说明「只查 XX 类资料」。如果这几类下面一份资料都没有，出题会明确报错并提示先传资料，不会偷偷退回全量资料。

建完之后，第 7 步**出题和跑测试**、第 8 步员工门户提问，都能选「用哪个助手」。同一个问题换个助手问，答案可能完全不同——这就是配置生效的证据。

第 6 步每张助手卡片上有个「**试问**」按钮：填一句话，当场真的调一次模型，返回回答和引用出处。改完提示词或范围，不用等到第 7 步就能验证有没有生效。

实测对比（同一份资料库，两个资料范围不同的助手各出一套题）：

| 助手 | 出的题 |
| --- | --- |
| 只查销售资料 | 新方案 35W 充电器的 MOQ 是多少？／欧规单价是多少？ |
| 只查产品资料 | 双口车充同时用总输出多少？／G67 彩盒尺寸和每箱数量？／Q8S 蓝牙版本？ |

范围为空时如实报错：`「售后政策助手」的资料范围是 售后资料，但这几类下面还没有资料。`

分类不准会影响助手能查到什么。资料分类可以改（`PATCH /api/clients/:id/docs/:docId`），改完助手范围跟着变。

**第 7 步 · 知识库测试**

- 点「生成测试题」：模型**从你上传资料的真实切片里抽题**，不是预置题库。默认 12 道，可调 5–30 道
- 出题跟着第 7 步选的助手走：岗位定位写进 system prompt，抽题池限定在该助手的资料范围内
- 批量运行，逐条给出 AI 回答与引用出处；答案来自 RAG，不是写死的
- 标「关键」的题必须人工判定（通过 / 需修改 / 资料不足），可以改判，统计实时更新
- 通过率 ≥ 85% **且所有题都判定完**，才允许生成报告
- 报告写入后，「测试与验收」页读的是同一份数据，不是写死的示例

**第 8 步 · 员工试用**

- 添加成员：写入成员表，「成员与权限」页同步；邮箱选填，只做备注
- **系统不发邮件**。加完成员点「复制门户链接」，把链接发给对方就能用
- 提问计数来自「员工门户」的真实问答，问 5 次自动满足条件
- 可以记录试用反馈，反馈内容回流到本步骤
- 成员被移除导致人数不足时，本步骤退回「进行中」

**第 10 步 · 开启使用（交付完成之后）**

交付完成不等于员工能用。第 10 步走完后，页面上会出现一张「开启使用」卡片，由客户自己按下开关：

- 开启前给四项真实体检：十步全完成 / 至少一个助手 / 知识库有切片 / 资料已入库。任何一项没满足，按钮是灰的，并直接告诉你差什么
- 服务端会再核一遍（`POST /api/clients/:id/go-live`），不满足返回 409 和缺口清单——员工是真的会打开这个链接提问的，不能只靠前端状态
- 开启后显示员工入口地址、可一键复制，附「进入使用界面」和「暂停使用」
- **没开启时员工门户是关着的**：打开链接会看到「员工门户还没开放」，写明需要管理员在第 10 步开启。管理员可以点「先预览界面」看效果，页面顶部有一条黄色预览条
- 暂停只关门，不删数据：资料、助手范围、测试记录、问答历史都保留，随时可以再开

开关状态存在 `state.json` 的 `project.live = { on, at, by }`。首页、项目卡、待办、侧栏「员工门户」的角标都跟着它变，不会出现「进度 100% 但员工其实用不了」这种错位。

## 功能模块

### 客户端（app.html）

- **工作台** —— 项目进度、待办事项、最近动态、服务入口
- **服务商城** —— 三项服务对比、开通申请 / 诊断预约（都会生成真实工单）

- **测试与验收** —— 真实题数 / 判定 / 通过率统计、报告下载 CSV、重新运行测试、验收记录落盘
- **员工门户** —— 带引用出处的 RAG 问答、按助手切换、真实缺口问题清单；支持多轮追问、Excel 参数表自动出 Markdown 表格、「新对话」清空上下文

- **设置** —— 企业信息、清空数据的正确入口说明
- **全局搜索**（Ctrl+K）—— 搜资料、助手、测试题、成员、步骤，点结果直接跳转

### 服务商后台（admin.html）

- 独立登录页：密码由**服务端**校验并加密落盘；前端只保留初始凭据用于「一键填入」，改过密码后这个按钮会失效
- 4 项经营指标（客户 / 进行中 / 合同金额 / 待处理工单），全部实时计算
- 按阶段划分的项目看板；客户表可按阶段真筛选
- **人员管理**（重点）：
  - 服务商团队：新增 / 编辑 / 删除 / 停用，这些人会进新建客户的「负责人」下拉
  - 客户工作人员：选一家客户，新增 / 编辑 / 删除它的成员，与客户端同一份数据
  - 编辑后台账号：显示名、角色、登录邮箱、密码（密码加密落盘）
- **客户档案编辑**：企业名、联系人、金额、负责人、计划交付、备注都能改，改完同步到工作区
- **新建客户**：写入档案 + 同步生成空白工作空间；金额不填就不编造
- **工单处理**：客户端提交的协助 / 诊断 / 开通申请会出现在这里，能填回复并标记完成
- **我的任务**：由未处理工单 + 客户进度动态生成，不再写死「本周 6 项」
- **导出周报**：真的下载 CSV（客户 / 工单 / 人员三张表）
- 交付情况统计读真实数据，没有「3 套模板 / 复用率 64%」这类编造数字

## 员工问答：连续追问与表格化回答

### 为什么做

真实员工不会每句话都写完整问题。问完「GC25 输出多少瓦」，下一句多半是「那它能给笔记本充吗」。
拿这句直接去 BM25 检索，命中率断崖式下降——这是单轮 RAG 最容易被放弃的地方。

另外，报价单 / 规格表在库里是 CSV 文本。只要求模型「简洁回答」，它会把参数写成一段散文，
员工还得自己从段落里抠数字。真实缺口记录里就有「用规格化的格式写参数」「excel 里的原文直接复制出来」这两条。

### 追问怎么走

`/api/clients/:id/chat` 接受 `history`（最多 6 条，每条截 400 字）：

1. **查询改写**：有历史、且最新一句是短追问或含「它 / 那款 / 相比 / 呢」等指代时，
   先用一次轻量模型调用改写成独立问题（`那它能给笔记本充吗` → `GC25能给笔记本充电吗`）。
   **改写只用于检索**；生成回答仍用员工原话 + 最近三轮对话，语气才自然。
   超时或失败一律降级回原句，追问不会因改写出错而答不出来。完整独立的问题不触发改写，省一次调用。
2. **上下文**：最近三轮对话原样传给模型，但资料每轮重新检索，旧片段不污染本轮答案。
3. **看得见**：改写生效时气泡里显示一行「接着上一轮理解为：…」，员工能判断系统有没有听懂。
   头部「新对话」清空上下文；切换助手也清空，避免不同岗位的回答串味。

### 表格怎么出

命中 `xlsx / xls / csv` 切片（或带「工作表」表头的 OCR 表格）时，提示词按问法分两档：

- 问「有哪些型号 / 列出单价 / 参数 / 对比」→ 强制 Markdown 表格，表头与数值照抄原文，
  资料没写的格子填「—」而不是编造；
- 其他问法 → 涉及多字段时优先用表格，单个值一句话回答即可，不硬凑。

服务端还有一道**输出护栏**：只有一行、且几乎没有有效数据的空表格会被自动剔除，
保留模型写的「缺哪个字段、该补什么资料」。提示词约束不住所有模型，后处理更可靠。

前端把 Markdown 表格安全渲染成 HTML 表格（先转义再解析，模型输出里的 HTML 标签一律当文本），
窄屏可横向滚动，不会撑破页面。

### 边界

- 多轮后**最近几轮对话内容会一并发给模型服务商**（用于指代消解）。这是比单轮更多的数据流，
  接入真实企业时要写进数据策略并取得书面确认。
- 上下文只存在浏览器内存里，刷新页面即清空；不落盘、不做会话持久化。
- 检索仍是中文 BM25，没有引入向量库。改写解决的是「指代」，不是「同义词」。

## 技术说明

纯静态，零依赖，零构建：

```
gsmett/
├── index.html          登录 / 注册
├── app.html            企业工作空间（客户端）
├── admin.html          服务商后台
└── assets/
    ├── css/app.css     设计系统（约 900 行）
    ├── js/data.js      业务模型、种子数据、图标库、工具函数
    └── js/app.js       路由、视图渲染、交互逻辑
```

- **无框架**：原生 DOM + 模板字符串，避免原型阶段引入构建链
- **无外部请求**：字体走系统栈，图标为内联 SVG，离线可用
- **状态持久化**：`localStorage` 键 `tm_state_v3`，刷新不丢；设置页可一键重置
- **路由**：hash 路由（`#wizard/6`、`#config/model`），可前进后退
- **响应式**：1440 / 980 / 860 / 620 四个断点，移动端侧边栏收起

### 本地运行

```bash
# 任意静态服务器均可
python -m http.server 8080
# 或
npx serve .
```

直接双击 `index.html` 也能打开（无跨域依赖）。

## 一个重要的边界

平台负责 **引导、配置、检查、管理**；真正涉及客户电脑、服务器、文件、模型 API 的操作，必须经由客户授权的本地执行程序或人工确认完成。

具体来说：

- 平台 **没有** 远程命令执行能力
- 服务顾问 **看不到** 客户的资料内容，只能在授权后查看部署状态与错误日志
- 授权范围明确、可随时撤销、全程留痕
- 客户资料默认存放在企业自有环境，平台只保存流程与状态信息
- 即使文件存在本地，检索片段与提问仍会发送到模型服务商 —— 这是 RAG 架构的固有数据流，必须由企业书面确认
- 开启多轮追问后，最近几轮对话内容与改写请求也会发给模型服务商；如企业不允许，应关闭追问改写

这些约束在产品里都做成了可见的界面元素（授权卡片、边界提示、数据策略表），而不是藏在协议里。
